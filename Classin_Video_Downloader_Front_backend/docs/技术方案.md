# ClassIn 视频下载管理系统 · 技术方案

> 版本 1.0 ｜ 技术栈：Python 3.12 + FastAPI + SQLAlchemy + SQLite（WAL）｜ 前端：Vue 3 + Element Plus（本地 vendor，免构建）

## 1. 背景与目标

ClassIn 平台的回放视频只能通过其网页端逐个下载，缺少批量能力与进度管理。本系统提供：

- **课堂批量导入**：CSV/XLSX 导入或手工录入，upsert 幂等去重；
- **课堂同步**：从 ClassIn 控制台 API 拉取最新课堂（纯 HTTP，复用 SSO Cookie），按钮触发、幂等入库；
- **任务化下载**：把"选中的课堂"快照成任务，后台线程调用 Selenium 引擎下载；同步到的新课在同步页勾选后一键建任务下载；
- **实时进度**：状态机 + 轮询接口，前端看板展示任务/课堂/视频三级进度；
- **2-3 人公网使用**：登录鉴权、登录限速、Cookie 脱敏、统一错误格式。

**非目标**：多任务并行（单浏览器实例 + SQLite 单写者，并发收益为负）、分布式部署、迁移工具（Alembic）。

## 3. ER 图（文本）

```
User 1 ──< DownloadTask 1 ──< TaskItem > ──1 Lesson
                │
                └──1──< DownloadLog

Lesson 1 ──< VideoAsset（单段视频下载状态与服务器文件索引）
DownloadTask 1 ──< VideoAsset（最近一次处理该视频的任务，可空）

Course（控制台「班级管理」页镜像，course_id UNIQUE）—— 与 Lesson 通过 class_id 逻辑关联（不建外键）

AppSetting（单行，id=1）
```

| 实体 | 关键字段 | 约束/索引 | 说明 |
|------|---------|----------|------|
| User | username, password_hash, role | username UNIQUE | PBKDF2-240k 哈希；role 预留只读成员 |
| Lesson | lesson_id, class_id, lesson_name, start_time, start_ts, status, sync_pending, unit/end_time/duration/teacher_name/class_status/record_state/live_state/website_synced_at | lesson_id UNIQUE；status/class_name/sync_pending/start_ts 索引 | 平台侧业务主键 upsert；字符串时间保真（start_time）+ epoch（start_ts，供视频库日期区间筛选，见 core.timeutil）；sync_pending=同步新增且未纳入任务；网站侧字段来自控制台「课堂管理」页，duration=endTime-startTime（秒） |
| Course | course_id, course_name, teacher_name, creator_name, class_total, complete_class_num, student_num, course_state, first_class_begin_time, end_time, add_time, cat_name, synced_at | course_id UNIQUE | 控制台「班级管理」页镜像（`/course/web/list`）；幂等 upsert |
| DownloadTask | status, save_dir, percent, counts, error | status/created_at 索引 | 状态机权威数据；counts 为聚合冗余（省 JOIN） |
| TaskItem | task_id+lesson_id, 快照字段, status, video_* | (task_id, lesson_id) UNIQUE | **快照设计**：任务运行中改课堂不污染任务 |
| DownloadLog | task_id, level, message | task_id 索引 | 增量游标 `id > after_id` 拉取 |
| VideoAsset | lesson_id, source_key, status, file_path, size_bytes | (lesson_id, source_key) UNIQUE；status 索引 | 逐段视频台账；API 不暴露服务器文件路径 |
| AppSetting | cookie, save_dir, max_workers…, sync_cookie(遗留), sync_days, last_sync_*, classin_account, classin_password | id=1 单行 | 明文 Cookie/密码只存库，API 永远脱敏；**Cookie 已统一**（登录/同步/下载共用 `cookie` 一份，`sync_cookie` 为遗留字段不再读取）；last_sync_* 回显同步结果；账号密码为备用（暂不自动登录，用于 Cookie 失效时人工重登） |

**级联**：`DownloadTask` 删除时 `cascade="all, delete-orphan"` 级联删 items/logs；`VideoAsset.task_id` 置空以保留文件索引；`foreign_keys=ON` PRAGMA 保证 SQLite 真正执行。

## 5. 关键流程

### 5.1 任务状态机（唯一迁移点：TaskService）

```
                ┌──────── pause ────────┐
                ▼                       │
created ──start──> running <──resume── paused
                │   │  │                 │
        engine异常│  │  └──stop──> stopping
                ▼   │                  │(stop信号优先)
             failed <┘                 ▼
        (可 restart)               cancelled ──start──> running
   全部课成功: success ──start──> running（重跑，items 重置）
```

- `RESTARTABLE = (created, failed, cancelled, success)`；`ACTIVE = (running, paused, stopping)` 占用全局闸门；
- 终态判定（`_finalize`）：**stop 信号优先 → cancelled；有课成功 → success；全失败 → failed**；
- 重跑前 items 全量重置为 pending（否则旧 failed 污染本轮聚合）。

### 5.2 并发模型

```
API 线程池 ──(_runtime_lock 闸门)──> start/pause/resume/stop/delete
                                          │
                                          ▼
worker 线程（daemon, 独立 SessionLocal）──> 引擎 download_videos
   └── 4 个回调（log/progress/course_status/lesson_done）
          └── runtime.lock 串行写 DB；progress 0.5s 节流落库
```

- **单任务闸门**：`_runtime` 单例 + `_runtime_lock`；start 在锁内完成"校验→重置→写状态→起线程"，杜绝并发插入；
- **线程安全**：回调来自引擎线程池 → 全部经 `runtime.lock`；进度走"内存必更、DB 节流"两层（防 SQLite 写放大）；
- **读不阻塞**：轮询 GET 不拿闸门锁，任务运行中前端依然流畅；
- **崩溃恢复**：启动时 `recover_stale_tasks()` 把残留 running/paused/stopping 统一置 failed。

### 5.3 安全

| 面 | 措施 |
|----|------|
| 口令 | PBKDF2-SHA256 ×240k 迭代 + 随机 salt；`hmac.compare_digest` 常时比较 |
| 会话 | JWT HS256，7 天；payload 仅 id/username/role（实时查库不缓存权限） |
| 爆破 | 5 次失败锁 5 分钟，key=`username@IP`（进程内，单机足够，fail-closed） |
| Cookie | 明文只存 SQLite；API 只出 `mask_cookie()`；第三方库 DEBUG 日志已降噪 |
| 公网 | HOST 默认 127.0.0.1（需显式改 0.0.0.0 才暴露）；500 只回 request_id 不回堆栈 |
| 上传 | CSV/XLSX 只读解析，白名单列名，行数上限 5000；路径拒控制字符 |

### 5.4 前端轮询策略

- 任务列表/详情：2s 轮询；日志：`after_id` 游标增量（空页回传原游标，防倒退）；
- 状态非 active 时降频（前端按 status 判断），避免无谓请求。

### 5.5 课堂同步（按钮式）

```
"立即同步"按钮 ──> SyncService.run（_sync_lock 非阻塞闸门，撞上直接 409）
        │
        │  控制台 API：POST /coreapi/school/asSubList（验活，errno!=1 即 Cookie 失效）
        │             POST /classroom/web/class/list（时间窗+分页，纯 JSON）
        │
        │  upsert（lesson_id 去重，空值不覆盖；新增→sync_pending=1）
        ▼
待下载新课表（GET /sync/pending，勾选粒度=课堂）
        │  "下载所选" ──> POST /tasks（快照 item、清 sync_pending）──> POST /tasks/{id}/start
        ▼
常规下载任务（与手工建任务完全同轨：状态机/闸门/日志/重跑）
```

- **接口对齐实证**：`classId`=课堂ID、`courseId`=班级ID、`name`/`courseName`=课堂/班级名、`startTime`/`createdAt`=秒级时间戳，与既有 CSV 导入数据逐行对齐 304/304；`searchStatus` 参数实测会把结果过滤为空（来自打包产物的枚举语义不一致），故不传；
- **同步与下载解耦**：同步只负责"拉取+入库+标 pending"，不隐式产生下载；下载是用户在待下载表中显式勾选后的动作，避免后台自动下单不可控；
- **勾选粒度=课堂**：建任务时把课堂下的全部视频片段快照进 item；已开课课堂前端默认预选，未开课的不预选（无回放，避免"必然失败"的下载）；
- **失败可回显**：`last_sync_status/message` 无论成败都落库并在同步卡回显；失败也刷新 `last_sync_at`；
- **建任务与手动完全同轨**：复用 TaskService（快照/目录回退/清 `sync_pending`），不存在两套漂移规则；启动失败时任务保留（created 态），可在任务页手动启动。

### 5.6 控制台镜像同步（班级同步页 + 课堂管理页叠加对比）

```
"立即同步"/"从网站同步" ──> ConsoleService.run_sync（复用 SyncService._sync_lock，撞上 409）
        │
        ├─ fetch_courses        POST /course/web/list        ──> upsert courses（course_id 去重）
        └─ fetch_console_lessons POST /classroom/web/class/list ──> upsert lessons（写网站侧字段，空值不覆盖本地）
                                     │
                                     ▼
                        GET /api/console/courses（班级/课程表）
                        GET /api/console/lessons（课堂表 + 下载对比：none/partial/done/failed）
                                     ├─ 展开行 GET /api/console/lessons/{id}/segments（片段级对比）
                                     └─ 展开行 GET /api/console/lessons?class_id=（按班级取课堂，支持勾选）
                                             │
                                             ├─ 整班一键下载 POST /api/console/courses/{course_id}/download
                                             └─ 下载所选课堂 POST /api/tasks + PUT /api/tasks/{id}/start
```

- **两页面各一张表**：班级同步页 ← `courses`（控制台「班级管理」）；课堂管理页 ← 扩展后的 `lessons`（控制台「课堂管理」）；
- **保留本地能力**：课堂页原有 编辑/删除/导入/建任务 不变，只叠加网站字段与下载对比列；
- **班级下载入口**：班级同步页每行「下载本班课堂」（整班）与展开后勾选「下载所选课堂」；两者最终都落到同一下载任务体系（`POST /api/tasks` + `start`），任务详情统一弹出；
- **下载状态判定**（聚合 `VideoAsset`）：有成功且无失败=`done`、有成功也有失败=`partial`、仅失败=`failed`、无记录=`none`；`downloaded_at`=`max(updated_at) where status in (success,skipped)`（仅课堂级展示，不新增列）；
- **片段级匹配**：以文件大小为主键（`VideoAsset.size_bytes` ↔ 网站 `Size`，容差 1%）；网站有本地无→"未下载"；本地有网站无→`local_only`；
- **Cookie 统一**：登录 / 同步 / 下载共用系统设置里的 `cookie` 一份（`CourseService._cookie` 与 `SyncService` 均只读它，`sync_cookie` 为遗留字段）；班级同步页不再有独立的 Cookie 表单，仅保留"验证 Cookie"按钮（走控制台接口级验活）；
- **Cookie 失效提醒**：结果文案含"过期/未登录/失效"时前端告警条联动 `cookieExpired`；Cookie 过期走 422，需人工重登后到系统设置更新（不做自动登录：控制台登录含图形/滑块验证码，账号密码仅存库备用）。

## 6. 风险与应对

| # | 风险 | 影响 | 应对 |
|---|------|------|------|
| R1 | 单任务闸门：无法并行多任务 | 吞吐上限 | 当前部署固定单 Uvicorn worker；多进程前需改为数据库级锁/队列 |
| R2 | SQLite 写锁竞争（高频回调） | `database is locked` | WAL + busy_timeout=30s + 进度 0.5s 节流 + 回调单锁串行 |
| R3 | 进程崩溃残留 running | 任务卡"运行中" | 启动时 recover 兜底 + worker finally 双保险 |
| R4 | 公网暴露（0.0.0.0） | Cookie/数据泄露 | 默认只绑本机；限速；错误不回堆栈；文档要求反代加 TLS/Basic-Auth |
| R5 | 驱动与浏览器版本不匹配 | 任务启动失败 | `driver_auto` 自动下载匹配驱动；设置页环境自检；错误落任务日志 |
| R6 | 引擎为外部拷贝，上下游漂移 | 回调字段失配 | `courses_override` 字段对齐表写死在 worker（单点适配层）；升级引擎时只改这里 |
| R7 | 进度回调覆盖状态（竞态脏写） | 已暂停被改回运行中 | 回调只在 running 态写进度；status 迁移仅在 service 层 |
| R8 | Cookie 过期 | 下载全失败 | 启动 fail-fast + 在线验证接口 + 任务日志给出可读原因 |
| R9 | Cookie 单一来源（统一下载/同步共用）失效 | 全线失败 | 统一存于系统设置 `cookie`；同步页/系统设置均可一键验活（控制台接口级 asSubList errno）；过期走 422 + 前端 `cookieExpired` 告警，需人工重登更新 |
| R10 | 控制台接口字段/参数随版本漂移 | 同步"成功"但丢行/全空 | 归一化层多候选字段名（`_pick`）；字段映射以 304/304 对齐实证并记录在案；`searchStatus` 实测会滤空故省略；分页有 total+MAX_PAGES 双收敛 |
| R11 | 磁盘文件名非 UTF-8（历史/外部工具产生） | 扫描入库/媒体下发抛 `UnicodeEncodeError: surrogates not allowed` | `core.fsutil` 做路径可逆编解码：正常路径原样存、含代理路径加 `\u0001` 前缀 + UTF-8(surrogateescape)↔Latin-1 映射；哈希键走 `fsencode`；`Content-Disposition` 走 `quote_from_bytes(os.fsencode())`；标题用 `display_name` 替换为 U+FFFD |

## 7. 质量标准核验

- **PEP8/静态检查**：`python -m pyflakes backend run.py` 全绿（vendored 引擎除外，保持与上游一致不改）；
- **注释密度**：AST 统计 1170/3973 ≈ **29%**（按钮式同步改造后复测；`sync_service` 32%、`task_service` 27%、全文件均有模块/函数 docstring），以 "Why" 型决策注释为主；
- **异常与校验**：Pydantic 格式层 + BizError 业务层 + 全局 handler 兜底三层，全部走统一 `{code, code_str, message, request_id}`；
